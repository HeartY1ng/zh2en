# 原理与实现细节

## 两层，各用最合适的工具

| 层 | 用什么 | 为什么 |
|---|---|---|
| 候选词后面的英文 | 本地词典（CC-CEDICT） | 每个候选词都要查，必须瞬间返回、完全离线 |
| 打字时的整句直译 | 苹果 Translation 框架 | 离线、免费，大约 0.03 秒一句，可以边打边出 |
| 打完一句的地道版 | 大模型（默认 DeepSeek） | 翻译模型追求"忠实"，要换成母语者的说法并讲解，得靠大模型 |

翻译模型会把"加班加到吐了"老老实实译成 *until I vomited*，这是它的本分。我们要的是另一件事：**母语者在同样的场合会怎么说**，再加上一句讲解。这是改写，不是翻译。

## 第一层：候选词后面加英文

鼠须管（Rime）处理每次按键都会走一条流水线：

```
按键 → 处理器（processors）→ 切分 → 翻译器（拼音 → 候选）→ 过滤器（filters）→ 候选框
```

`english_hint.lua` 是挂在**最后一个**的过滤器。它拿到一串候选词，逐个查表，查到了就把英文接在注释后面，然后原样交出去。候选的顺序和数量都不变。改注释的写法（`cand:get_genuine().comment`）跟雾凇自带的 `corrector.lua` 一样。

### 词典怎么清洗（`dict/build_dict.py`）

CC-CEDICT 原本约 12.5 万条，是给"学中文的外国人"用的。给"中国人学英语"用，噪音很多：

| 问题 | 例子 | 处理 |
|---|---|---|
| 一个词有多个读音，常用的反而排在后面 | 东西：dōngxī = east and west，dōngxi = thing | 按释义多少排序：释义多的读音通常更常用 |
| 冷门读音 | 的（dī）= 的士 | 冷门读音只有一个释义时，不显示 |
| 释义里夹着中文和拼音 | 打：…打伞[da3 san3]… | 整条丢掉 |
| 对学英语没用的条目 | variant of…、surname…、CL:… | 丢掉 |
| 太长 | 北京：Beijing municipality, capital of… | 只取逗号前那段，最多 26 个字符 |
| 动词前面的 to | to work overtime | 去掉 to |

清洗后剩大约 10.9 万条，在鼠须管里第一次用时读进内存，之后每次查表都是瞬间完成。

## 第二层：整句浮窗

两个程序靠一个小文件传话：

```
鼠须管 ── sentence_tap.lua ──写──▶ $TMPDIR/zh2en/live.json ──系统通知──▶ Zh2En.app
                                   {sid, committed, composing, done}
```

### sentence_tap.lua（鼠须管这一侧）

- 排在处理器列表的**最前面**，但对所有按键一律回答"我不管"（`kNoop`），所以不会影响打字，只是先看一眼。
- 用 `commit_notifier` 记下上屏的字，用 `update_notifier` 记下正在打、还没上屏的部分。
- 退格删一个字。打出 。！？，或者按回车（而且这句里有汉字），就算这句结束。Esc、方向键、⌘ / ⌃ 快捷键（粘贴、撤销……）会让这句作废，因为这时已经跟踪不到真实的文本了。
- **英文模式下打的字一律不记**：那可能是密码、命令或验证码。
- 写文件时先写 `.tmp` 再改名，浮窗程序永远读不到写了一半的内容。文件放在系统临时目录里：不进 Time Machine 备份，重启就清空，浮窗收起时浮窗程序还会把它删掉。

### Zh2En.app（浮窗这一侧）

- 用 kqueue 监听那个目录：文件变了由系统通知，闲着时零唤醒。早期版本每 0.1 秒看一次文件，空闲时每秒要唤醒 13 次。
- 停顿 0.25 秒后调用苹果翻译，不是每个按键都翻。
- 一句话打完，而且是 DeepSeek 模式、句子不敏感，才调用一次大模型。
- 隐私过滤：不含汉字的内容不处理；含长串数字、邮箱、网址、"密码 / 验证码"之类词的句子，只做本地直译，不往外发。
- 浮窗是一个"永远不会成为当前窗口"的面板：点它右上角的开关，光标还留在你打字的输入框里。它默认不出现在截图和屏幕共享里。
- 点浮窗外面就收起：用全局鼠标监听（只收得到"点在别的程序上"的事件，点浮窗本身不会触发；监听鼠标不需要辅助功能权限）。收起时记下这句话当时的完整原文，之后同一句里只显示比它多出来的部分。是否"鼠标正停在浮窗上"，每次直接问鼠标的实际位置，不靠悬停标记（悬停标记可能因为没收到"离开"通知而卡住）。
- 可以拖动：位移用屏幕坐标算（窗口自己在动，用窗口内坐标会抖）。松手后记下"底边中点"，之后变高时向上长，靠近屏幕边缘会收回屏幕内；记下的位置已经不在任何屏幕上时（比如拔了外接显示器），回到默认位置。

### 外观：极光玻璃

- 底子用 SwiftUI 的 `glassEffect`（液态玻璃）。
- 里面有 4 条模糊的彩色光带从左往右飘。**句子越长，光带一条一条地多出来、飘得越快**，而不是同一层颜色越来越浓。这是踩过坑的：第一版用整块网格渐变，句子一长就糊成一片。
- 每上屏一个字，玻璃上掠过一道淡淡的反光；一句话打完，一道亮的反光扫过，光带亮一下。
- 地道版里的关键说法带一层缓缓流动的渐变色。提示词要求模型讲解的"说法"必须原样摘自它给的英文句子，这样才能在句子里找到并标色。
- 动画限制在每秒 30 帧，只在浮窗显示时才跑。

## DeepSeek：两个坑

1. 现在的模型是 `deepseek-flash` 和 `deepseek-v4-pro`。实测 flash 约 0.8 秒一句，pro 约 1.3 秒，地道程度差不多，所以默认用 flash。
2. 它们默认会先"思考"：几百个 token 花在推理上，`max_tokens` 用完了，正文还是空的。请求里加上 `"thinking": {"type": "disabled"}`，0.6 秒就能拿到结果。

### 提示词要点

- 说母语者在**同样场合**会说的话，不要直译，长度跟原句差不多。
- 碰到文化特有的说法（比如打招呼用的"吃了吗"），给出英语里同样场合会说的话（*How's it going?*），而不是 *Have you eaten?*。
- 不许把不常用的说法讲成"常见用法"。
- 输出 JSON：`{"en": "...", "note": "说法 = 中文解释"}`。

## 调试工具

```bash
helper/.build/Zh2En --test 今天加班加到吐了。 你吃了吗？   # 不经过输入法和浮窗，直接测两层翻译
helper/.build/Zh2En --demo                                   # 用真实浮窗播放示例（可以录屏）
helper/.build/Zh2En --snapshot out.png 0.6                   # 把浮窗画成图片看排版（画不出玻璃效果）
helper/.build/Zh2En --render-demo frames/                    # 离线逐帧渲染演示动画（README 的 GIF 就是这么做的）
helper/.build/Zh2En --render-candidates candidates.png       # 画候选框示意图
/usr/bin/log show --last 10m --predicate 'subsystem == "io.github.zh2en"'   # 只有事件、没有内容的日志
```

### 生成 README 里的演示 GIF

不录屏，而是让程序一帧一帧地把浮窗画出来，背景是固定的示意壁纸。这样做不需要"屏幕录制"权限，也不会把你屏幕上玻璃后面的聊天、文档录进去，每次生成的结果都一样。离屏画不出真正的液态玻璃，所以用半透明白底来模拟。

```bash
helper/.build/Zh2En --render-demo /tmp/zh2en-frames
ffmpeg -framerate 15 -i /tmp/zh2en-frames/frame_%04d.png \
  -vf "fps=12,scale=860:-1:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff:max_colors=200[p];[b][p]paletteuse=dither=bayer:bayer_scale=5:diff_mode=rectangle" \
  -loop 0 assets/demo.gif
```

想录真实屏幕也可以：先 ⌘⇧5，再运行 `open -n ~/Applications/Zh2En.app --args --demo`。演示模式下浮窗允许被录制，平时则不出现在截图和录屏里。
